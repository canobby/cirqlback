Why this port is cheap

A repo audit confirms the entire reward-bridge backend is already game-agnostic and wired: game_progress.state is a jsonb blob (new fields need zero schema change), the tap → in-game reward hook is live inside processTap, and game achievements already mint real badges via awarderRole:"game". So the work is mostly a client-engine swap (retire ~1,300 lines of ring game, drop in the CirqlBreak canvas engine) + catalog reshape. The only genuinely-new build is a cross-player daily-score leaderboard.

Progress — updated 2026-07-04

P0, P1, P2 and P3 are complete — 16 of 20 issues shipped and auto-deployed live to /play. The core game, the tap→Supernova reward bridge, the cross-player Daily leaderboard, and the meta layer (cosmetic skins, achievements, galaxy map) are all live and validated in-app. Only the optional app-store track (P4) and QA remain. Latest (playtest polish): controls redesigned into an off-field spin dial — the play screen is now a column with a Pulse / dial / Supernova band below the circle, so your thumb never covers the field.

Decisions locked · risks · dependencies

Locked decisions

  • Endless-unique levels via procedural + modifiers, not AI — determinism is required for a shared Daily. AI only later for flavor (names/lore), never geometry.
  • Ship integrated in /play first (fastest to real users + the reward bridge); evaluate standalone app after.
  • The reward bridge is the moat — nobody else does "tap a coffee shop → multiball."

Risks & watch-items

  • Daily leaderboard is the only net-new backend + the one needing a guarded DDL apply-script (db:migrate is broken on the shared DB).
  • Client is untrusted — anti-cheat is pragmatic deterrence, not DRM.
  • iOS Safari has no web haptics — degrade gracefully; native shell (P4) restores it.
  • Party co-op needs real two-human playtesting to tune.
